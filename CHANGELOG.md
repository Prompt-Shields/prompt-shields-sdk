# Changelog

All notable changes to the Prompt Shields SDK and platform are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Asset modality in the AI-BOM and webhooks** (#75): `/ingest/events` accepts `modality` only from the set the gateway emits (`text`, `image`, `audio`, `document`, case-insensitive); any other value is stored as null and counted as `modality:invalid` in `/telemetry/loss`, and the batch is still accepted. The CycloneDX export (`/partner/v1/export?format=cyclonedx`) carries a `promptshields:modality` property on each asset that has one, and webhook asset payloads include `modality`. Gaining a first modality does not emit `asset.changed` (that would fire once for every existing asset after upgrading); the next event for the asset carries it. Gateway telemetry for `/v1/images/edits` now carries the requested `model` (it was `unknown`), read from the form the handler already parsed, as transcriptions do since #176.
- **Collector: encrypted per-tenant provider admin credentials and key fingerprint corroboration** (#93): a tenant's OpenAI and Anthropic admin keys for the org usage pull can now be stored per tenant instead of only in `PS_PROVIDER_ADMIN_KEYS`. Use `/api/v1/admin/provider-credentials/{provider}` (tenant API key) or `/partner/v1/provider-credentials/{provider}` (new scope `provider-credentials:manage`, never granted by default) to store (`POST`), rotate (`POST …/rotate`), read masked and delete a key. The key is write-only: responses show the last four characters, the encryption key id and timestamps, never the key. Keys are sealed with AES-256-GCM under the existing `PS_WEBHOOK_SECRET_KEYS` keyring, with their own derived key, bound to the tenant, provider and row, and re-encrypted with the active keyring key when a pull uses them. The keyring code moved from `collector/webhooks.py` to a shared `collector/secret_keyring.py`; webhook tokens are unchanged. `PS_PROVIDER_ADMIN_KEYS` still works as a fallback for providers with no stored key. Pull results now report `credential_source`. Ingest now stores the SDK's `api_key_fingerprint` (`sha256(key)[:16]`) on usage events instead of ignoring it. A value that is not 16 hex characters is dropped and counted as `api_key_fingerprint:invalid`. Provider usage APIs report only key ids and never a key or hash, so the collector cannot compute the fingerprint. A tenant registers `PUT /provider-key-fingerprints/{provider}/{api_key_id}` with the fingerprint instead. The platform_signal asset for that key and the SDK asset that saw the same fingerprint and model then corroborate each other and become `verified`. This runs on link and after every pull. Gateway events carry no fingerprint, so they are not matched by key. Migration `018` adds `provider_credentials`, `provider_key_fingerprints` (both with the `tenant_isolation` RLS policy, enforced at once if RLS is already on, and in the erasure order) and `ai_usage_events.api_key_fingerprint`.

- **TypeScript Partner SDK: attestations, risk suggestions, webhooks, extended usage, lockfile and npm publish workflow** (refs #105): `@prompt-shields/partner` adds `assets.attestations()` and `assets.attest()` (`/partner/v1/assets/{id}/attestations`), a `status` filter and the rule-suggestion fields (`status`, `source`, `ruleId`, `frameworkRef`, `evidence`, `reviewedAt`, ...) on `assets.risks()`, `totalTokensCached`, `totalTokensCacheWrite` and `totalTokensReasoning` on the usage summary, and `modality`, `region`, `lifecycleState`, `lifecycleChangedAt` and `attestation` on assets (plus `lifecycleState` as a list filter, and `lifecycleChange` and `attestationChanges` on change events). `client.webhooks.subscriptions` (`create`, `list`, `get`, `update` for PATCH pause/resume/edit, `delete`, `rotateSecret` with a grace period) and `client.webhooks.deliveries` (`list`, `redeliver`) wrap the tenant admin webhook API and need the tenant API key. `client.send()` reaches any other endpoint; it and `client.get()` take only a path relative to `baseUrl` (an absolute URL, `//host` or anything else that would send the bearer token to another host is refused). The webhook methods refuse a client built with partner OAuth credentials or a partner API key (`ps-pk-...`), so partner credentials are never sent to the admin API. POST requests are no longer retried after a network error or 5xx (only after 429), so an attestation or a secret rotation is not repeated. The hand-written types are now checked against `docs/openapi.yaml` by `test/openapi.test.ts` (`npm run check:openapi`; schema properties, required fields, enum values, query parameters and operations, both ways). `package-lock.json` is committed and CI uses `npm ci`. `.github/workflows/publish-partner-ts.yml` publishes on a `partner-ts-v<version>` tag with `npm publish --provenance --access public` after checking the tag against `package.json` and `src/client.ts`, that the commit is on `main`, and running the typecheck, tests and build; see `packages/partner-ts/RELEASING.md`. Not published yet: it needs the `@prompt-shields` npm org and an `NPM_TOKEN` repository secret.
- **Gateway: cached, cache-write, reasoning and service-tier usage in telemetry** (refs #9): ps-telemetry events now carry `tokens_cached`, `tokens_cache_write`, `tokens_cache_write_1h`, `tokens_reasoning` and `service_tier`, with the SDK's field names and semantics, on Chat Completions, Responses and Messages, streamed and not. Read from OpenAI `prompt_tokens_details.cached_tokens` / `completion_tokens_details.reasoning_tokens`, Responses `input_tokens_details` / `output_tokens_details`, Anthropic `cache_read_input_tokens` / `cache_creation_input_tokens` / `cache_creation.ephemeral_1h_input_tokens` / `usage.service_tier`, and the gateway's normalised Bedrock (`cacheRead/WriteInputTokens`) and Gemini/Vertex (`cachedContentTokenCount`, `thoughtsTokenCount`) usage. Streams take them from the usage chunk, Anthropic `message_start` + `message_delta` (latest value wins) or `response.completed`. `tokens_in` stays the whole prompt including cache reads and writes, as in the SDK. A cost the provider reports (OpenRouter `usage.cost`) is sent as `cost` with `cost_source: provider_reported`; otherwise no `cost` or `cost_source` is sent, since the gateway does not price calls itself. The tier echoed by the Responses adapter for non-native providers is not reported. A zero cached or reasoning count the gateway filled in for a value the provider did not report (Gemini/Vertex, Bedrock, the Responses adapter) is left out, as the SDK leaves it out. A reported cost of $10,000 or more (beyond the collector's `cost` column) is not sent. The Responses adapter's `usage.input_tokens_details` now carries `cache_creation_tokens` when the provider reported cache writes. The Anthropic chat transform now keeps `usage.cache_creation` (the cache-write TTL breakdown) on chat responses and the final stream chunk.
- **CI: GitHub Actions workflow** (refs #69, #8): `.github/workflows/ci.yml` runs on pull requests and pushes to `main` with `contents: read` permissions and cancels superseded runs. Jobs: the SDK on Python 3.11–3.13 (ruff for syntax errors and undefined names, pytest); the collector on Python 3.11 against `pgvector/pgvector:pg16` (single alembic head, `alembic upgrade head` on an empty database, then the collector tests as a non-superuser so row-level security binds); the gateway on Node 20 (`npm ci`, `tsc`, the default offline jest suite, `npm run build`); and the Partner TypeScript SDK (typecheck, jest, build). Three stale upstream guardrail suites that already fail on `main` (`plugins/default`, `qualifire`, `javelin`) are excluded in the workflow only, tracked in #69. See CONTRIBUTING.md.

- **Collector: store extended usage fields** (#9, #90, #75): fields the SDK and gateway already send are now stored on `ai_usage_events` instead of being discarded and counted in `ignored_fields`: `requested_model`, `served_model`, `tokens_cached` (cache reads), `tokens_cache_write`, `tokens_cache_write_1h`, `tokens_reasoning`, `cost_source`, `service_tier`, `framework`, `modality`, `usage_units` and `usage_unit_type`. OTel GenAI spans now store their requested and served model too. All are optional. Old events without them still ingest. A value of the wrong type, a negative or out-of-range count, or a string over its limit (256 characters for model names, 64 for labels) is stored as null and does not reject the batch; it is counted in `ignored_fields` as `<field>:invalid` so `/telemetry/loss` shows it. Assets now have a `modality` (text, audio, image or document), set from the first event that reports one. The internal registry and the Partner API return it on assets. The Partner API usage summary adds `total_tokens_cached`, `total_tokens_cache_write` and `total_tokens_reasoning`. Migration `017` adds the nullable columns. No new table, so the RLS policies and erasure order are unchanged. Still in `ignored_fields`: the gateway's `api_surface`, `route_*`, `cache_status`, `stream*`, `trace_id`/`retry_count`/`attempts`, and the SDK's `tokens_audio_*`, `web_search_requests`, `tokens_estimated`, `stream*`, `api_key_fingerprint`, `risk_tags` and `user_id`.
- **Gateway: `/v1/messages` for codex models via the Responses API** (refs #73, enterprise 2.16/2.20): Anthropic Messages requests for OpenAI and Azure OpenAI models that only the Responses API serves (`*codex*`, `o1-pro`, `o3-pro`, `gpt-5[.x]-pro`, deep research) are translated to a Responses request (`system` → `instructions`, messages → input items, `tool_use`/`tool_result` → `function_call`/`function_call_output`, tools and `tool_choice`, `thinking` → reasoning summaries, `output_config.effort` → `reasoning.effort`, `store: false`) and sent to the provider's `/responses`; the response is translated back, non-streaming and streaming (`message_start`, `content_block_*` for thinking, text and `tool_use` blocks, `message_delta` with usage and stop reason, `message_stop`). Usage keeps cache reads apart from `input_tokens`, so ps-telemetry reports the full input. `temperature`, `top_p` and `stop_sequences` are dropped (these reasoning models reject them). Other OpenAI models still use the Chat Completions adapter. Thinking is not round-tripped (no encrypted reasoning items).
- **Gateway: Responses API cancel and input-token counting** (#73, enterprise 2.25.1): `POST /v1/responses/{id}/cancel` (OpenAI, Azure OpenAI) cancels a background response, and `POST /v1/responses/input_tokens` (OpenAI) counts a Responses request's input tokens; the count request forwards only the fields OpenAI counts (`model`, `input`, `instructions`, `tools`, `tool_choice`, `reasoning`, `text`, `truncation`, `conversation`, `previous_response_id`, `parallel_tool_calls`). Other providers get a 400 (`invalid_request_error`, code `unsupported_operation`) without an upstream call. Both emit a ps-telemetry event (`api_surface: responses`) with no token usage: a cancel returns the usage of the generation it stopped, which the create call already reported, so ps-telemetry, `/metrics` and OTel do not count it again (cancel emits no GenAI span). Cancel responses are never cached.
- **ps-scan: GitHub Action, `--exclude`, `--fail-on`, `code_scan`/`otel` confidence** (#95, #92): a composite action at the repository root (`uses: Prompt-Shields/prompt-shields-sdk@<ref>`) installs the SDK from the action's own checkout, runs `ps-scan` to a SARIF file, writes the summary to the job summary, optionally uploads the SARIF to code scanning (`upload-sarif: true`, needs `security-events: write`) and fails afterwards when `fail-on` matched. `ps-scan --exclude GLOB` (repeatable or comma-separated) skips files and directories whose relative path or name matches; `ps-scan --fail-on any|KIND|VENDOR[,...]` exits 1 when a finding's kind or vendor matches, after the report is written. `DiscoverySource` (Python SDK and partner TypeScript client) gains `code_scan` and `otel`. Collector `compute_confidence` now weights `otel` as `high` (observed runtime GenAI spans, like the SDK and gateway; it fell back to `low`) and `code_scan` as `medium` (a code reference, not an observed call); duplicate entries of one source no longer count as corroboration. A self-scan test checks that scanning this repository finds the SDK, gateway and demo usages.
- **SDK: Python reference router for `route-policy.v1`** (refs #13): `prompt_shields.route_policy` (`parse_route_headers`, `build_route_request`, `resolve_route`) is a pure, deterministic port of the gateway router for policy replay: explicit group > quality hint > `heuristic` strategy, the `max_cost` budget clamp and the unknown-group fallback. It follows the gateway where Python and JavaScript differ (UTF-16 string length, `Number()` parsing of `X-PS-Max-Cost`, `Object.keys` order on budget ties, ASCII-only case folding). `test_route_policy_vectors.py` now runs the 19 active golden decision vectors through it (they were all skipped); the 19 `pending` sensitivity, data-policy and quality-bar vectors stay skipped with their reasons, and `resolve_route` does not apply those policy sections yet. Not exported from `prompt_shields` top level.

- **SDK: `prompt-shields-instrument` entry point** (#88): `prompt-shields-instrument python app.py ...` (or `prompt-shields-instrument app.py ...`, or `python -m prompt_shields.autoinstrument <command>`) runs an unmodified app with `prompt_shields.instrument()` applied at interpreter startup, like `opentelemetry-instrument`. It prepends a bootstrap directory with a `sitecustomize.py` to `PYTHONPATH` and execs the command, so the app and its Python child processes are instrumented, configured by the `PS_*` environment variables plus `PS_INSTRUMENT_VENDORS` (comma-separated). A `sitecustomize` already on the path still runs first (bootstraps from two SDK installs on the path skip each other). The bootstrap never stops the app: a missing `PS_API_KEY`, an SDK that fails to import or a failing chained `sitecustomize` is logged as a warning. Subprocess tests run a script that never imports the SDK against a local collector: one event under the entry point, none without it.
- **Gateway: regression suite for the ported 2.0 features** (#69): `gateway/src/tests/regression/` drives the full gateway app (every middleware mounted) offline, with a fake `fetch` serving canned provider responses and capturing the collector and OTLP payloads. It covers OpenAI, Anthropic, Bedrock and Vertex AI chat, streaming chat and embeddings (Anthropic embeddings refused without an upstream call); `/v1/rerank` (Cohere, Pinecone, Bedrock); the Responses and Messages adapters; `/v1/health`, `/metrics` and the JSON payload limit; Databricks and Latitude; OAuth client credentials and the Vertex/Bedrock host-credential gates; cache scope across callers; client stream cancellation; and OTel GenAI spans. Each LLM call checks the ps-telemetry event (`requested_model`, `served_model`, usage), and the active golden route-decision vectors are replayed through the app. `ps-telemetry` now reports rerank usage as `usage_units` with `usage_unit_type: search_units` (it was dropped). Suites that need live vendor APIs or `.creds.json` (tryPost and 17 guardrail plugins) moved from the default `npx jest` run to `npm run test:integration` (listed in `tests/jest/integrationSuites.js`); default run: 21 failing suites / 48 failing tests → 3 / 35, all stale upstream guardrail tests (`default` needs ESM `jose`, `qualifire`, `javelin`).
- **Docs: AI bill teardown methodology appendix and report template** (#15): `docs/teardown/methodology.md` explains how a teardown gets its numbers: data collected and consent, baseline, per-call cost (served vs. requested model, cache, batch and long-context dimensions, provider-reported vs. estimated, null-cost calls), sensitivity mix, policy replay assumptions and limits, statistical caveats, what a teardown does not claim, and a methodology record each report fills in. `docs/teardown/teardown-report-template.md` is the fill-in customer report. Sections that depend on the unbuilt CLI, replay and eval harness (#12, #13, #14) are marked pending.

Second slice of #74.
- **Gateway: upload size limit and transcription model in telemetry** — set `MAX_FILE_PAYLOAD_SIZE_IN_MB` to reject `multipart/form-data` (and `application/x-www-form-urlencoded`) uploads (audio transcriptions and translations, image edits, files) over the limit with 413 before the form is read into memory; while it is set, a multipart request without a valid `Content-Length` gets 411. Gateway telemetry and OpenTelemetry spans for `/v1/audio/transcriptions` and `/v1/audio/translations` now carry the requested `model` (it was `unknown`), read from the form the handler already parsed; no other form field and none of the audio is read or sent (#75).
- **Collector: webhook follow-ups — pause/edit, safe key rollout, secret sweep, robust verification samples** (#103): `PATCH /api/v1/admin/webhooks/subscriptions/{id}` (tenant API key) changes `url` (full destination checks again), `event_types` (known events the partner holds the scope for, also checked on resume) and `is_active` (pause/resume); every call is audited with the changed field names. A delivery whose secret uses a key id the worker does not have (a rolling restart that adds a key) is no longer dead-lettered: the attempt is counted and retried with the normal backoff, logged once per key id; the docs give the safe rollout order (add the new key after the active one everywhere, then make it active). The worker's hourly cleanup and `python -m collector.webhooks purge` now also clear rotated-out secrets whose grace period is over on idle subscriptions (tenants listed through a logged RLS bypass, rows cleared per tenant). The documented Python and Node.js signature checks, and `webhooks.verify_signature`, return false for malformed headers (`t=1,v1=x,junk`, non-ASCII, non-string) instead of raising; tests now run both documented samples.
- **Collector: EU AI Act risk rule review follow-ups** — `eu_ai_act_article_5` 1.1.0: the Article 5(1)(f) exception no longer accepts the bare word "safety" ("workplace safety", "child safety" hid the critical flag); it now takes specific medical or safety contexts (medical, clinical, therapeutic, driver or pilot fatigue, drowsiness and alertness monitoring, road and aviation safety). `eu_ai_act_annex_iii` 1.3.0: the 4(a) recruitment exclusion for non-employment applicants is now a list of phrases around the applicant or candidate term (`loan* applicant*`, `university applicant*`, `applicant* for a visa*`, `election* candidate*`, ...) instead of words anywhere on the asset, so "benefits", "university" or "credit" elsewhere no longer hide a job applicant; the 8(b) campaign-logistics exception drops bare "schedul*" and "administrative" for clear logistics phrases (event, volunteer, shift or staff scheduling, office administration), and voter targeting or persuasion still overrides it. Keyword phrases may now star any word (`loan* applicant*`); a star was previously only honoured at the end. The CycloneDX export emits each `risk:` / `risk-suggestion:<framework>:<category>` property once per asset (highest level) plus `…:<category>:rules` with the contributing rule ids, instead of repeating the name when several rules (e.g. Article 5 points) hit one asset (#97).
- **Collector: webhook follow-ups — encryption keyring, secret rotation grace period, `asset.attested`** (#103): `PS_WEBHOOK_SECRET_KEYS` (`kid:key,…`, first entry encrypts) replaces the single `PS_WEBHOOK_SECRET_KEY` for encrypting subscription signing secrets; stored secrets now record their key id (`v2.<kid>.…`), old secrets without one still decrypt with `PS_WEBHOOK_SECRET_KEY`, and secrets under an older key are re-encrypted when a delivery uses them or by `python -m collector.webhooks rekey` (tenants listed through a logged RLS bypass, each tenant rekeyed under its own context). `POST …/rotate-secret` takes an optional `{"grace_period_seconds": n}` (up to 7 days): until `rotation_grace_ends_at` the `Prompt-Shields-Signature` header carries a `v1` for the new and the old secret, and the docs' verification samples accept any matching `v1`. Recording an attestation queues `asset.attested` (scope `changes:read`) with field, state, actor type and time; `attested_by`, the comment and the attested value are left out as personal data. `PS_WEBHOOK_TIMEOUT_SECONDS` must now be above 0 and at most 60 (the claim lease is 300 s; a larger value meant nothing was ever sent), checked at startup. Migration `016` adds `previous_secret_ciphertext` and `previous_secret_expires_at` to `webhook_subscriptions`.
- **Collector: EU AI Act Article 5 and Article 50 risk suggestions** — two new rulesets in `collector/risk_rules/`. `eu_ai_act_article_5` (1.0.0) flags assets that resemble a prohibited practice under Article 5(1)(a)–(h) (manipulative or deceptive techniques, exploiting vulnerabilities, social scoring, individual crime prediction from profiling, untargeted facial image scraping, emotion recognition in the workplace or education, biometric categorisation inferring sensitive traits, real-time remote biometric identification for law enforcement) with `risk_level: critical`, category `prohibited_practice`, and a reference quoting the point; every match is a suggestion for human review, since keywords cannot establish the legal conditions or exceptions. `eu_ai_act_article_50` (1.0.0) suggests the transparency obligations (AI interaction disclosure for chatbots and assistants, marking synthetic audio/image/video, informing people exposed to emotion recognition or biometric categorisation, disclosing deep fakes and public-interest AI text) at `medium`. Rule conditions can now carry `context` (at least one must also match) and `exclude` (none may match) (#97).
- **Collector: cloud AI inventory follow-ups (Azure, AWS, Vertex AI)** — Long runs no longer fail part-way when credentials expire. Assumed AWS roles now get 1-hour sessions by default (`session_duration_seconds`, 900–43200), and the AWS session keys and the Azure and GCP access tokens are renewed before they expire. An AWS credential whose `regions` mix commercial and GovCloud, or whose `role_arn` is in another partition, is now rejected as a configuration error. Mixed partitions failed before, because keys and STS are per partition. Bedrock custom models that are still `Creating` are skipped. Azure: a subscription that fails (for example with a 403) is reported in `subscription_errors` and the other subscriptions still run. A malformed ARM response (invalid JSON, a body that is not an object, or items that are not objects) is now reported as a cloud error instead of a 500. `Disabled` deployments are skipped. `PS_CLOUD_INVENTORY` tenant keys match case-insensitively, and keys that are not UUIDs, or that repeat a tenant, are rejected. Unknown `clouds` values in the pull request return 400 instead of being dropped. Vertex AI: a deployed model registered in a different region from its endpoint is now named. It comes from that region's registry when that region is inventoried, and otherwise from a single model lookup. Tuned models from continuous tuning (`preTunedModel` with no `baseModel`) take their base model from the model they continued from. New tests check that the inventoried `region` appears in the registry API, the Partner API and the CycloneDX AI-BOM (under RLS) (#94).

- **SDK: auto-instrumented streaming for Gemini, Mistral, Cohere, Bedrock and Anthropic `messages.stream()`** — `instrument()` now also wraps google-genai `models.generate_content_stream`, mistralai `chat.stream` / `stream_async`, Cohere `chat_stream` (v1 and v2), boto3 `bedrock-runtime` `converse_stream` / `invoke_model_with_response_stream`, and the Anthropic `messages.stream()` / `beta.messages.stream()` helpers (which post directly and previously emitted nothing). Sync and async where the SDK has both. Like the OpenAI and Anthropic stream wrappers, each stream emits one event when it ends or is closed early (`stream_completed`), with usage from the vendor's final report: Gemini `usage_metadata`, Mistral's last chunk, Cohere `message-end` / `stream-end`, Bedrock ConverseStream `metadata.usage` and InvokeModelWithResponseStream `amazon-bedrock-invocationMetrics`; without it tokens are estimated (`tokens_estimated`). Chunks are passed through as they arrive and unchanged. Bedrock's `EventStream` and Anthropic's `MessageStreamManager` are observed in place, so callers keep the SDK's own objects (`isinstance` and attributes unchanged). For google-genai and Cohere, whose streams send the request on the first read, a request that fails before any chunk emits no event, as for a failed non-streamed call. Fail-open as before (#89).
- **ServiceNow connector (first slice)** — `python -m collector.servicenow --tenant <id> [--full]` or `POST /api/v1/admin/connectors/servicenow/sync` (operator only, `PS_ADMIN_TOKEN`; runs as the target tenant under row-level security) reads the registry through the Partner API with a scoped partner key (`export:read`, `changes:read`) and writes it to the CMDB through the Identification and Reconciliation Engine (`POST /api/now/identifyreconcile`), not the Table API, so CIs are identified and reconciled against other sources instead of duplicated. AI assets become CIs of a configurable class (default `cmdb_ci_function_ai`; see the follow-up entry below), vendors CIs of `cmdb_ci_service` by default, linked by a `Depends on::Used by` relationship. Each CI carries the AI-BOM `bom-ref` as `correlation_id` and as its `sys_object_source_info` native key, so re-runs update the same CIs; retired assets get `install_status` 7 / `operational_status` 6. Any IRE item or relationship error fails the run and the cursor (`/export`, then `/changes`) only moves when IRE accepted everything; `GET /api/v1/admin/connectors/servicenow/status` shows it. OAuth client credentials or basic auth come only from `PS_SERVICENOW` and are never stored, logged or returned; calls go only to `https://<instance_host>` (must end in `PS_SERVICENOW_ALLOWED_HOST_SUFFIXES`, default `.service-now.com`, and resolve to public addresses). Data flows, business units and risk mappings are not pushed yet, and it has not been verified against a live instance (#102).
- **Connectors: partner key must belong to the synced tenant** — `/partner/v1/export`, `/changes` and `/assets/{id}/data-flows` now return the credential's tenant as `meta.tenant_id`, and the shared connector reader (LeanIX and ServiceNow) refuses any response that does not name the tenant being synced, or names none, before anything is written to the target or the cursor moves. A partner key configured under the wrong tenant no longer moves one tenant's registry into another's workspace.

- **Collector: Postgres row-level security for tenant isolation (first slice)** — every tenant table gets a `tenant_isolation` policy keyed on the transaction-local settings `app.tenant_id` and `app.rls_bypass`. The collector sets the tenant once a tenant key, partner key or partner token is verified, re-applies it at the start of every transaction, and scopes credential lookups to a short bypass that ends with the lookup. Operator routes (`PS_ADMIN_TOKEN`) and the retention, lifecycle, audit-purge and reembed jobs use an explicit bypass that logs its reason on the `collector.rls` logger. The flow-rebuild and provider-usage jobs are scoped to one tenant instead. Migration `015` creates the policies but leaves them off. Turn them on with `python -m collector.rls enable`, run as the table owner; `status` and `disable` are also available. Enabling uses `FORCE ROW LEVEL SECURITY`, so the policies bind the owner as well. `PS_RLS_REQUIRED=true` stops the collector from starting unless the policies are enforced for its database role. With RLS on, a query that leaves out its tenant filter returns no rows, and a write to another tenant's rows fails in Postgres (#83).
- **SDK: LlamaIndex integration and global LangChain handler (#90)** — `prompt_shields.integrations.llamaindex.register()` attaches an event handler and a span handler to LlamaIndex's root instrumentation dispatcher and emits one event per LLM call (`chat`, `complete`, async and streaming; a stream is reported when it ends) with `framework: "llamaindex"`, vendor from the LLM class, token usage from the provider response or LlamaIndex's counts, tool names the model asked for and PII categories; `unregister()` removes both handlers from every dispatcher. The use-case hint is `register(use_case=...)`, then `ps_use_case` in LlamaIndex `instrument_tags`, then the outermost named agent (`FunctionAgent(name=...)`, an `AgentWorkflow`'s root agent) or your own `Workflow` subclass; LlamaIndex defaults (the agent name `Agent`, its own class names) are never used. Calls that reach a provider SDK patched by `instrument()` are reported once, by `instrument()`, also when a stream is read later or in another thread or task: LlamaIndex streams call the provider lazily, so their announced call is bound to the stream's generator (`defer_framework_call`) and claimed only by a provider call made while that generator runs. ### Changed

- **CI hardening** (refs #69): the collector job now runs `alembic check` after `alembic upgrade head`, so `packages/db/models.py` drifting from the migrations fails CI. The SDK job runs ruff's default rule set instead of only syntax errors and undefined names; the existing findings in `packages/sdk` were fixed mechanically (import order, unused imports and locals, `datetime.UTC`, sorted `__all__`), and the two intentional fail-open `except Exception` blocks in the telemetry sender are marked `noqa: BLE001`. Workflow actions moved off the deprecated Node 20 runtime: `actions/checkout@v5.1.0`, `actions/setup-python@v6.3.0`, `actions/setup-node@v5.0.0`; the ps-scan action uses `actions/setup-python@v6`, and its `python-version` input now documents that the interpreter stays on `PATH` as `python` for later steps in the job.
- **ps-scan: misspelled `--fail-on` tokens are reported**: a token that is not `any`, a finding kind or a known vendor is now named in a warning on stderr and ignored (it was silently ignored, so `--fail-on antropic` never failed). If none of the tokens is known, ps-scan exits 2 with a usage error before scanning, so the GitHub Action step fails instead of passing.
- **SDK: `instrument()` patches google-genai, mistralai, cohere and boto3 when they are imported** — instead of importing every installed SDK up front (about 0.9 s of startup with all of them installed), `instrument()` patches a module at once if it is already imported, and otherwise through an import hook when the app first imports it; `uninstrument()` removes the hook. Calling `instrument()` at startup and importing or creating clients afterwards works as before. openai and anthropic are still imported and patched up front, unchanged (#88, #89).
- **SDK: abandoned streams are reported** — a stream from an instrumented call that the caller leaves without reading to the end or calling `close()` (a `break` out of the loop) now emits its event when it is garbage-collected, once, with `stream_completed: false` and `stream_abandoned: true`. The event is queued, not sent, inside the garbage collector and goes out with the next flush; nothing is emitted at interpreter shutdown, and a google-genai stream dropped before its first read made no request and emits nothing. An Anthropic `messages.stream()` manager that is never entered gives back a framework call it claimed. `ShieldsClient` streams are unchanged (#88, #89).
- **SDK: stream telemetry follow-ups (exit flush, Cohere early close, `ShieldsClient` abandoned streams)** — Events still buffered when a short script exits (an abandoned stream's event, a send that failed) are now sent by one best-effort `atexit` flush, bounded by a total budget of 2 s (`instrument(exit_flush_timeout=...)` or `PS_EXIT_FLUSH_TIMEOUT`; `0` or `PS_DISABLE_EXIT_FLUSH=1` turns it off). It never raises, keeps a 429 back-off, and only covers senders registered by `instrument()` / `ShieldsClient` / `AsyncShieldsClient`; `uninstrument()` and `close()` / `aclose()` unregister them. A forked child process (a gunicorn or multiprocessing worker) starts with an empty buffer and its own client id: the events queued before the fork are sent by the parent only, not again by each child's flushes or exit flush. Leaving a Cohere `chat_stream` loop early (sync or async) is now reported as an early close (`stream_completed: false`, without `stream_abandoned`), like `close()` on an OpenAI or Anthropic stream, and its event is queued instead of sent with a blocking flush from the generator's close (which can run in the garbage collector). A raw Cohere `chat_stream` context that is never entered gives back its framework claim when collected. `ShieldsClient` and `AsyncShieldsClient` streams now also report abandoned streams (queued, `stream_abandoned: true`). The `latency_ms` of a stream that ends early without an error now runs to the last chunk read, not to the close or the garbage collection. LlamaIndex `register()` / `unregister()` keep tracking handlers they failed to remove, so a later call retries instead of leaving them attached and untracked (#88, #89).
- **SDK: Cohere clients created before `instrument()` are instrumented** — cohere's `Client` stores bound `chat` / `chat_stream` methods on each instance when it is created, so patching those missed clients built earlier. `instrument()` now patches the raw clients they call (`RawBaseCohere`, `RawV2Client` and their async versions); calls made through `with_raw_response` are reported too. Cohere versions without raw clients keep the previous behaviour (#89).
- **SDK: LlamaIndex `register()` is fail-open** — if the installed LlamaIndex's dispatcher does not accept the handlers, `register()` logs a warning, leaves nothing half-attached and returns None instead of raising; `unregister()` logs its errors too (#90).
- **Connectors: ServiceNow and LeanIX review follow-ups (#101, #102)** — ServiceNow now writes AI assets to the CMDB CI Class Models store app (1.75.0+ to be safe; sources cite 1.68.0–1.75.0) AI classes: `cmdb_ci_function_ai` (AI Function, externally hosted / SaaS; the new `asset_class` default, replacing the non-existent `cmdb_ci_ai_application`) and `cmdb_ci_appl_ai_application` (AI Application) for assets whose vendor is in the configurable `self_hosted_vendors` (`self_hosted_asset_class`, `null` to disable); the guide documents the required store app version and the independent identification rule on `correlation_id`. Both connectors refresh their OAuth token shortly before `expires_in` runs out and once after a `401` (a second `401` fails the run; no retry loop; tokens never logged). A non-string `last_seen` / `first_seen` / `changed_at` from the Partner API no longer raises `TypeError` (HTTP 500): the value is ignored, and any remaining malformed data fails the run as `invalid response data`. LeanIX gets `business_unit_type` (`Organization`, default, or `UserGroup` for the earlier meta model) and an optional `lx_workspace` sent as the LDIF `lxWorkspace`. OpenAPI: `PaginationMeta.tenant_id` / `sync_token` no longer claim to be returned only by `/changes`.
- **SDK: Anthropic `tokens_in` now counts cached prompt tokens** — it is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`, the total prompt size, matching OpenAI `prompt_tokens`. Before, it was `input_tokens` alone, which leaves cache reads and writes out. For prompt-cached workloads, Anthropic `tokens_in` and `cost` will both rise: cache tokens used to be left out of the cost, and are now billed at the cache read and write rates. Use `tokens_cached` and `tokens_cache_write` for the split (#9).

### Security

- **Gateway response cache is scoped to the caller** — the cache key was a hash of the request body and endpoint only, so with caching on, caller B could be served caller A's cached response for an identical body, and identical bodies sent to different `/v1/proxy` paths shared one entry. The key now also covers a SHA-256 digest of the provider, the caller's credential and identity fields (API key, `Authorization` and other credential headers, virtual key, Vertex service account, AWS role, Azure/OAuth client, org/project), any header the gateway forwards upstream (all non-`x-portkey-` headers on `/v1/proxy`, plus `forward_headers`; tracing headers excluded) and the full upstream URL (custom host, path and query). Raw credentials never appear in the key. Keys stay stable for the same caller, including Bedrock `assumedRole`/`serviceRole` while STS credentials rotate. Existing cache entries are unreachable after upgrade (a one-time miss).
- **Gateway: Azure host identity only goes to Azure** — with `AZURE_AMBIENT_CREDENTIALS_ENABLED=true`, `azureAuthMode` `managed` and `workload` (`azure-openai`, `azure-ai-inference`) mint a token for the gateway host's own Azure identity, and a caller could send it anywhere: a `custom_host` or `x-portkey-custom-host`, a resource name such as `evil.example#`, a non-Azure `azureFoundryUrl`, or the Azure proxy path `/v1/proxy/evil.example/x.openai.azure.com/...`. These modes now return 400 before any token request unless there is no custom host, the resource name matches `^[a-z0-9][a-z0-9-]{0,62}$`, and the Foundry URL and final upstream URL are `https`/`wss` on a Microsoft Azure AI host (`*.openai.azure.com`, `*.cognitiveservices.azure.com`, `*.services.ai.azure.com`, `*.models.ai.azure.com`, `*.inference.ai.azure.com`, their `.azure.us`/`.azure.cn` equivalents) with no port or user info. `azureEntraScope` must be the Cognitive Services audience (`https://cognitiveservices.azure.com|us|cn`, optionally `/` or `/.default`), so a caller cannot ask for, say, a `management.azure.com` or `storage.azure.com` token; the only storage token is the one the gateway itself requests to download Azure OpenAI batch output, and only that download may go to Azure Blob Storage (a proxy path such as `/v1/<account>.blob.core.windows.net/...openai.azure.com` is refused). Caller credentials (API key, `azureAdToken`, `entra` with a client secret) still work with custom hosts. Azure ML online endpoints (`*.inference.ml.azure.com`) can no longer use host identity. The Azure guardrails (`contentSafety`, `shieldPrompt`, `protectedMaterial`, `pii`) with `managed` likewise refuse a custom host or a resource name outside that pattern and fail closed; they now ask IMDS for a `https://cognitiveservices.azure.com/` token instead of passing `resourceName` as the IMDS resource.
- **Gateway cache skips multipart and binary requests** — with simple caching on, every multipart (`/v1/audio/transcriptions`, file uploads) or binary body serialised to `{}` and got the same cache key, so one audio file could get another's cached transcript. The cache now only reads and writes JSON request bodies; FormData, Blob, ArrayBuffer, typed-array and stream bodies always go to the provider (cache status `DISABLED`).
- **Collector tenant ingest keys are hashed** — tenants now store a SHA-256 lookup prefix and a bcrypt hash instead of the plaintext key in `settings`. Migration `004` hashes existing keys and removes the plaintext; downgrading cannot restore them. An unknown key and a wrong key get the same 401 after the same bcrypt work (#81).
- **Gateway admin console and log stream require auth** — `/public` and `/log/stream` now need `PS_GATEWAY_ADMIN_TOKEN` (at least 16 characters) as a bearer token or session cookie, and the log stream is disabled when it is unset. Previously anyone who could reach the gateway port could watch live request logs. Provider options and headers are redacted in the stream. Ported from upstream Portkey `main` (#54).
- **`x-portkey-forward-headers` loop guard** — requests or configs that try to forward the forward-headers header itself are rejected with 400 (upstream `de0e6c5`, #55).
- **Upstream URL SSRF check** — provider URLs built from request fields (Azure resource name, Vertex region, AWS region, account ids) may no longer point at metadata, private, link-local or alternatively encoded IPs (#65).
- **Credential masking in gateway logs** — bearer tokens, API keys, AWS and Google keys, and passwords in URLs are masked in the shared logger, the Redis connection log and error logs (#65).
- **Config fan-out cap** — at most 100 root targets (1000 for conditional routing) and 50 nested targets per root target; override with `MAX_ROOT_CONFIG_TARGETS`, `MAX_CONDITIONAL_ROOT_CONFIG_TARGETS` and `MAX_NESTED_CONFIG_TARGETS` (#65).
- **Custom-host response size cap** — responses from custom hosts are limited to 50 MiB (`PS_MAX_CUSTOM_HOST_RESPONSE_BYTES`) (#65).
- **Provider credentials win on proxy routes** — forwarded or proxied client headers no longer overwrite the credential headers a provider config sets (#65).
- **Bedrock/SageMaker cannot borrow the gateway's AWS identity** — `awsAuthType=serviceRole`, and `assumedRole` without operator-configured keys, sign with the host's credentials only when `AWS_AMBIENT_CREDENTIALS_ENABLED=true`; otherwise `serviceRole` returns 403. `assumedRole` without a role ARN returns 400 instead of signing with the operator's assume-role keys. Upstream 2.0 allows all of these for any caller (#108).
- **Azure callers cannot borrow the gateway's Azure identity** — `x-portkey-azure-auth-mode: managed` (host managed identity via IMDS) and `workload` (host federated token) on Azure OpenAI and Azure AI Inference, and `managed` credentials on the Azure guardrails, work only when `AZURE_AMBIENT_CREDENTIALS_ENABLED=true`; otherwise the request returns 403 and the guardrail fails closed (verdict `false`). Upstream allows them for any caller.
- **AWS signed requests stay on AWS** — a crafted `x-portkey-aws-region` (`x@evil.example/`) or S3 bucket name could point Bedrock, SageMaker or STS calls, and their signed headers (access key id, session token), at another host. Regions are now format-checked, signing is refused for hosts outside `AWS_ENDPOINT_DOMAIN`, and STS `RoleArn`/`ExternalId` are URL-encoded (#108).
