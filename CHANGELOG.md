# Changelog

All notable changes to the Prompt Shields SDK and platform are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Collector: Postgres row-level security for tenant isolation (first slice)** — every tenant table gets a `tenant_isolation` policy keyed on the transaction-local settings `app.tenant_id` and `app.rls_bypass`. The collector sets the tenant once a tenant key, partner key or partner token is verified, re-applies it at the start of every transaction, and scopes credential lookups to a short bypass that ends with the lookup. Operator routes (`PS_ADMIN_TOKEN`) and the retention, lifecycle, audit-purge and reembed jobs use an explicit bypass that logs its reason on the `collector.rls` logger. The flow-rebuild and provider-usage jobs are scoped to one tenant instead. Migration `015` creates the policies but leaves them off. Turn them on with `python -m collector.rls enable`, run as the table owner; `status` and `disable` are also available. Enabling uses `FORCE ROW LEVEL SECURITY`, so the policies bind the owner as well. `PS_RLS_REQUIRED=true` stops the collector from starting unless the policies are enforced for its database role. With RLS on, a query that leaves out its tenant filter returns no rows, and a write to another tenant's rows fails in Postgres (#83).
- **Collector: risk classification suggestions (EU AI Act, ISO 42001, NIST AI RMF)** — a rules engine suggests `risk_mappings` from registry fields and the telemetry-derived data flows (data sources, output destinations, detected PII, classification). Rules are versioned JSON in `collector/risk_rules/`: `eu_ai_act_annex_iii` covers all eight Annex III areas, `data_protection` maps PII and restricted data to NIST AI RMF and ISO/IEC 42001 Annex A. Each suggestion has `status: suggested`, `source: rules`, its `rule_id`, `ruleset_version`, `framework_ref`, `confidence` and `evidence` (which signal and value matched which keyword or PII category). Run it with `POST /api/v1/admin/risk-suggestions/run` or `python -m collector.risk_suggestions --tenant <id>` / `--all-tenants`; confirm or reject with `POST /api/v1/admin/risk-mappings/{id}/review`, which records `reviewed_by` (required, the person deciding) and the tenant key prefix. The engine only touches rows that are still `suggested`, never re-suggests a reviewed rule, and skips framework/category pairs that already have a hand-entered mapping. Registry and Partner API risk reads return the new fields and accept `?status=`; the registry hides rejected rows by default, the Partner API returns only `confirmed` rows by default so existing integrations do not receive unreviewed suggestions; the CycloneDX export lists suggestions as `risk-suggestion:*` properties. Migration `014` adds the columns (existing rows become `confirmed` / `manual`) (#97).
- **Collector: change webhooks for partners (first slice)**: a tenant admin can subscribe a partner credential to `asset.created`, `asset.changed` and `asset.retired` events under `/api/v1/admin/webhooks/subscriptions`. Ingest, OTel ingest and the lifecycle sweep write events to an outbox in the same transaction as the change, and a worker delivers them later (`python -m collector.webhooks deliver --loop`, or `PS_WEBHOOK_WORKER_INTERVAL_SECONDS`). Requests carry `Prompt-Shields-Signature: t=…,v1=HMAC-SHA256`. Each subscription has its own secret, which is shown once and stored AES-GCM-encrypted under `PS_WEBHOOK_SECRET_KEY`. Failed deliveries retry with backoff up to `PS_WEBHOOK_MAX_ATTEMPTS`, then appear in a dead-letter view (`GET /deliveries`) and can be redelivered. Endpoints must use https and resolve only to public addresses, which is checked when the subscription is created and again on each delivery. The request goes to the checked IP, redirects are not followed and proxies are not used. Only active, unexpired partners holding the event's scope receive events: asset events need `changes:read` (Phase 1 `registry:read` covers it), checked when events are queued and again before each send. Payloads leave out owner email and content. An attempt has an overall deadline (`PS_WEBHOOK_TIMEOUT_SECONDS`), and NAT64 (`64:ff9b::/96`), IPv4-compatible and site-local IPv6 destinations are refused. The docs include signature verification samples. Migration `013` (#103).
- **SDK: multi-dimensional pricing (first slice)** — `estimate_cost` now prices service tiers (OpenAI `flex`/`batch`, Anthropic and Gemini `batch` at 50%, stacking with cache discounts), Anthropic 1-hour cache writes (2x input), long-context bands (Gemini 2.5 Pro and Claude Sonnet 4 above 200k prompt tokens), OpenAI audio tokens (`gpt-4o[-mini]-audio-preview`) and Anthropic web search fees ($10 / 1,000). Adapters and streams read `service_tier` (Chat Completions, Responses, Anthropic `usage`), `prompt/completion_tokens_details.audio_tokens`, `cache_creation.ephemeral_1h_input_tokens` and `server_tool_use.web_search_requests`, and events carry them as `service_tier`, `tokens_audio_in`/`_out`, `tokens_cache_write_1h` and `web_search_requests`. A provider-reported cost (OpenRouter `usage.cost`) wins over the table, also for unpriced models, with `cost_source="provider_reported"`. Tiers or audio tokens with no known price (e.g. OpenAI `priority`) give `cost: null` rather than a standard-rate guess. New golden cost vectors in `schemas/pricing/cost-vectors.v1.json`, hand-computed from list prices, for the gateway to share. Gateway pricing, per-unit (page, character, second, image) prices and collector persistence of the new fields are not included yet (#71).
- **Collector: human attestation workflow (first slice)** — owners can sign off an asset field separately from source-count `confidence`, which attestation never changes. `POST`/`GET /api/v1/registry/assets/{id}/attestations` (tenant key) and `/partner/v1/assets/{id}/attestations` (`assets:read` to read, new opt-in `attestations:write` scope to write, never in the default scopes or the legacy `registry:read` alias) record a state (`unreviewed`, `attested`, `disputed` with a required comment, `retired`) for `asset`, `owner` or `data_classification`, with who (`attested_by` plus the tenant key prefix or partner id), when, comment and a snapshot of the value. History is append-only in the new `asset_attestations` table (triggers reject UPDATE, and DELETE outside tenant erasure). Registry and Partner asset reads, `/partner/v1/export` and `/partner/v1/changes` now include an `attestation` block per field with `value_changed` when the registry value moved since sign-off; `/changes` adds `attestation_changes`. Every attestation call writes a `partner_audit_log` row. Other fields such as risk classification plug in with `register_attestable_field`. Migration `012` (`012_asset_attestations.py`) (#98).
- **Partner API: granular scopes and rate-limit tiers** — every `/partner/v1/*` route now requires its own scope (`assets:read`, `data-flows:read`, `risks:read`, `usage:read`, `changes:read`, `export:read`) and returns `403`, recorded in the audit log, without it. Scopes not granted are denied, including the new `webhooks:manage`. Phase 1 `registry:read` credentials and tokens keep working: the scope stands for the six read scopes and never gains new ones. A token is checked against its credential's current scopes, so narrowing a credential applies before its tokens expire. Credentials get a rate-limit tier (`basic` 120, `standard` 1000, `premium` 5000, `enterprise` 20000 requests/minute) or a custom limit; existing credentials keep their own limit. The admin API adds `PATCH /api/v1/admin/partner-credentials/{id}` and `GET /api/v1/admin/partner-scopes`, and new credentials default to the read scopes. Migration `011` adds `partner_credentials.rate_limit_tier` (#106).
- **Collector: cloud AI inventory, Azure (platform signal)** — reads Azure OpenAI and AI Foundry model deployments, read-only, through Azure Resource Manager with a `Reader` (or narrower custom-role) service principal. Each deployment becomes a `medium`-confidence asset with `discovery_source=["platform_signal"]`, `calling_service="azure:<deployment resource id>"`, its `region`, and owner / environment / business unit from resource tags (tags fill empty fields only). Re-runs update the same assets. Per-tenant credentials come only from `PS_CLOUD_INVENTORY` in the operator environment; trigger with `POST /api/v1/admin/cloud-inventory/pull` (operator only, `PS_ADMIN_TOKEN`; 404 when unset) or `python -m collector.cloud_inventory`. Migration `010` adds `ai_assets.region`, now returned by registry and Partner API asset reads and as an AI-BOM `region` property. AWS Bedrock and Vertex AI are not covered yet (#94).
- **SDK: Gemini, Bedrock, Azure OpenAI, Mistral and Cohere adapters** — `get_adapter()` now returns adapters for `google` (the existing `GeminiAdapter`, now registered), `bedrock` (boto3 `converse`, and `invoke_model` read from the `x-amzn-bedrock-*-token-count` headers without consuming the body, or a parsed Anthropic, Nova or Llama body), `azure_openai`, `mistral` and `cohere` (v2 and v1, billed units). They read SDK objects or raw JSON, import no vendor SDK, and follow the usage accounting rules: `tokens_in` includes cache reads and writes, plus cached, cache-write and reasoning counts where the vendor reports them. A new `ProviderAdapter.pricing_model()` picks the priced model id: Azure maps deployment names through `AzureOpenAIAdapter(deployments={...})` or uses the served model without its version date, and Bedrock drops cross-region inference profile prefixes (`us.`, `eu.`, ...). Pricing adds Gemini 2.x, Bedrock Claude, Nova and Llama, Mistral and Cohere entries; Azure OpenAI falls back to OpenAI list prices (`PRICING_VENDOR_FALLBACK`). Wrapping and auto-instrumenting these SDKs is not included yet (#89).
- **Telemetry event-loss accounting (SDK and collector)** — the SDK counts events that never reach the server by reason (`buffer_overflow`, `send_failed`, `rate_limited`, `server_skipped`, `shutdown`), exposes them with `client.telemetry_stats()`, and sends a `metadata` object (random client id, per-client monotonic batch `seq`, cumulative `enqueued_total` and `dropped`) with every collector batch, never to atlas. A `429` re-buffers the batch and pauses sends for `Retry-After` (capped at 300 s). New `ShieldsClient.close()` does a final flush and counts what is left. The collector stores, per tenant and client, the events it received, the losses the SDK reported, batches it rejected (`rate_limited`, `write_failed`) and unknown event fields it ignored, in the new `telemetry_client_stats` table (migration `009`). `GET /telemetry/loss` reports them with an `unaccounted` gap and a `coverage` ratio (#87).
- **Collector: data flows derived from telemetry** — `/ingest/events` now accepts `data_sources`, `output_destination`, `detected_pii_types` and `region` (the SDK already sends the first three) and, like OTel spans, upserts the asset's `data_flows` on ingest: `input` flows from each data source (or the calling service) to `vendor/model[@region]`, and an `output` flow to `output_destination`. Each flow keeps its event count, first and last seen, highest classification and the union of PII categories, including `national_id`. `python -m collector.data_flows --tenant <id>` (or `--all-tenants`) rebuilds flows from stored events, idempotently and per tenant. Migration `008` adds `ai_usage_events.flow_context`, `data_flows.event_count`/`first_seen`/`last_seen` and a unique flow key (#96).

- **Gateway: OpenTelemetry GenAI spans (semconv 1.40)** — opt-in with `PS_OTEL_ENDPOINT`: one span per LLM call exported as batched, fail-open OTLP/HTTP JSON (no new dependencies, works on Workers) with `gen_ai.operation.name`, `gen_ai.provider.name`, request/response model, normalised `gen_ai.response.finish_reasons`, `gen_ai.usage.*`, `error.type`, `X-PS-*` business context and `traceparent` propagation. Prompt and completion content is off unless `PS_OTEL_CAPTURE_CONTENT=true`. The collector's `/ingest/otel/v1/traces` accepts these spans; `PS_API_KEY` is sent as the bearer only for an endpoint set via `PS_OTEL_ENDPOINT`, never for the generic `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`. Do not also run `PS_API_KEY` telemetry against the same collector: each call would be ingested twice (#70).
- **Gateway: per-attempt retry telemetry** — every upstream attempt for a request (retries and fallback targets) is now recorded, and the gateway telemetry event carries an `attempts` array (attempt number, provider, model, HTTP status, latency, coarse `error_class` such as `rate_limited` or `server_error`), plus `retry_count` and a `trace_id` (the caller's `x-portkey-trace-id`, else a generated id). A `500 → 429 → 200` chain yields three linked attempts. Existing event fields are unchanged; no request or response content, error messages or headers are recorded. The collector does not persist the new fields yet (#78).
- **Gateway: eight OpenAI-compatible chat providers** — `minimax`, `byteplus` (ModelArk) and `lightning-ai` from the Portkey enterprise changelog, plus EU-hosted `berget` (SE), `scaleway` (FR), `regolo` (IT), `ionos` (DE) and `stackit` (DE) for sovereignty and cost routing. All use fixed vendor base URLs and the OpenAI chat transforms; all but MiniMax and Lightning AI also route `/v1/embeddings`. First slice of #74.
- **Gateway: keyless upstream auth (first slice)** — OpenAI and OpenAI-compatible (`custom_host`) upstreams accept OAuth 2.0 client credentials (`x-portkey-oauth-token-url`, `-client-id`, `-client-secret`, optional `-scope` / `-audience`) instead of a static key. The token URL must be `https`, pass the upstream SSRF check and is refused for IP literals and loopback or internal names; `OAUTH_TOKEN_URL_ALLOWED_HOSTS` restricts it to a list. Tokens are cached per token URL, client id, secret hash and scope, refreshed before expiry, and secrets never appear in errors or logs. Vertex AI accepts `x-portkey-vertex-auth-type: workload` to use the gateway host's Google identity (metadata server / GKE Workload Identity), refused with 403 unless `GCP_AMBIENT_CREDENTIALS_ENABLED=true` (#76).
- **SDK: auto-instrumentation** — `prompt_shields.instrument()` patches the installed `openai` (`chat.completions.create`, `responses.create`) and `anthropic` (`messages.create`) SDKs, sync and async, so unmodified call sites emit the same events as `ShieldsClient`, streams included. Configuration comes from arguments or `PS_*` environment variables. It is idempotent, `uninstrument()` reverses it, it skips missing packages and is fail-open, and calls made through `ShieldsClient` are not counted twice. The no-code-change entry point is not included yet (#88).
- **Collector: data flows derived from telemetry** — `/ingest/events` now accepts `data_sources`, `output_destination`, `detected_pii_types` and `region` (the SDK already sends the first three) and, like OTel spans, upserts the asset's `data_flows` on ingest: `input` flows from each data source (or the calling service) to `vendor/model[@region]`, and an `output` flow to `output_destination`. Each flow keeps its event count, first and last seen, highest classification and the union of PII categories, including `national_id`. `python -m collector.data_flows --tenant <id>` (or `--all-tenants`) rebuilds flows from stored events, idempotently and per tenant. Migration `008` adds `ai_usage_events.flow_context`, `data_flows.event_count`/`first_seen`/`last_seen` and a unique flow key (#96).

- **Collector: audit log for registry reads** — every `/api/v1/registry/*` read, semantic search included, now writes a `partner_audit_log` row with tenant, the SHA-256 prefix of the API key (never the key), route, asset ids, query params (secrets redacted, search text hashed), status, result count and time. Partner API reads use the same writer and now also record asset ids and query params. Migration `007` (`007_registry_read_audit.py`); `python -m collector.audit purge` deletes rows older than `PS_AUDIT_RETENTION_DAYS` (default 365) (#84).
- **Collector: stale and retired asset detection** — assets with no telemetry for `PS_ASSET_STALE_AFTER_DAYS` (default 30) become `stale`, and after `PS_ASSET_RETIRE_AFTER_DAYS` (default 90) `retired`; new telemetry reactivates them. New `lifecycle_state` / `lifecycle_changed_at` fields and `?lifecycle_state=` filter on registry and Partner API asset lists, `lifecycle_change` in `/partner/v1/changes`. Run the sweep with `python -m collector.lifecycle` or `POST /api/v1/admin/asset-lifecycle/sweep`. Migration `006` (`006_asset_lifecycle.py`) (#100).
- **Collector: AI-BOM export as CycloneDX 1.6** — `GET /partner/v1/export?format=cyclonedx` (scope `registry:read`) returns the tenant's registry as a CycloneDX 1.6 ML-BOM: apps as `application` components, models as `machine-learning-model` components, vendors as services carrying data flows, dependencies from each app to its model and provider, and discovery source, confidence, owner and risk classification as `promptshields:` properties. Tests validate it against the official schema (#104).
- **Collector: local embeddings for semantic search** — `PS_EMBEDDINGS_BACKEND=openai|local|none` (default `auto` keeps today's behaviour). `local` uses fastembed in-process via the optional `local-embeddings` extra, so asset metadata never leaves the box; `none` makes `/search` fall back to keyword matching instead of meaningless mock vectors. `PS_EMBEDDINGS_OPENAI_BASE_URL` targets any OpenAI-compatible endpoint. `python -m collector.reembed` rebuilds the index after a switch (#86).
- **Collector: provider org usage pull (platform signal)** — pulls daily usage from the OpenAI organization usage API and the Anthropic Admin usage report, per project/workspace, API key and model. Keys nobody instrumented appear as `medium`-confidence assets with `discovery_source=["platform_signal"]`; re-runs overwrite the same buckets. Admin keys come from `PS_PROVIDER_ADMIN_KEYS`; trigger with `POST /api/v1/admin/provider-usage/pull` (operator only: `Authorization: Bearer $PS_ADMIN_TOKEN` and a `tenant_id` in the body; 404 when the token is unset) or `python -m collector.provider_usage_admin` (#93).
- **Collector: data retention and tenant erasure** — per-tenant `retention_days` (default `PS_RETENTION_DAYS_DEFAULT=365`), a batched, idempotent purge of old `ai_usage_events` (`python -m collector.retention purge` or `POST /api/v1/operator/retention/purge`), and `DELETE /api/v1/operator/tenants/{id}` for erasure. Operator routes need `PS_ADMIN_TOKEN`. Purges and erasures are recorded in the new `retention_audit_log` table (migration 005). Read paths can use `retention_cutoff(tenant)`; the Partner API usage-summary now clamps its window to it (#85).
- **SDK: cached, cache-write and reasoning token accounting** — events now carry `tokens_cached` (OpenAI `prompt_tokens_details.cached_tokens`, Anthropic `cache_read_input_tokens`, Gemini `cachedContentTokenCount`), `tokens_cache_write` (Anthropic `cache_creation_input_tokens`) and `tokens_reasoning` (OpenAI `completion_tokens_details.reasoning_tokens`, Gemini `thoughtsTokenCount`), for both plain and streamed responses. Anthropic `tokens_in` now includes cache reads and writes, matching OpenAI and the gateway. `estimate_cost` charges cache reads and writes at their own rates (vendor defaults, overridable per model), and events gain `cost_source` (`pricing_table`, or `pricing_table_estimated_tokens` when tokens were estimated). A `GeminiAdapter` parses Gemini responses but is not wired into the clients yet (#9).
- **Gateway `/v1/ocr`, ElevenLabs and Deepgram** — `POST /v1/ocr` (Mistral OCR shape) for Mistral, Vertex-hosted Mistral and Azure AI Foundry; `elevenlabs` and `deepgram` providers for `/v1/audio/speech` and `/v1/audio/transcriptions`, with transcripts mapped to the OpenAI shape. Telemetry now emits `modality` (text, audio, image, document) and non-token usage (audio seconds, OCR pages, speech characters) (#75).
- **Collector: OTel GenAI ingest** — `POST /ingest/otel/v1/traces` accepts OTLP/HTTP JSON traces with the same tenant key as `/ingest/events` and turns `gen_ai.*` spans into usage events with discovery source `otel`. Other spans are ignored. Prompt and completion content attributes and span events are always dropped. Bodies are capped at 4 MiB and 2000 spans. Protobuf is not supported yet (#92).
- **Partner API `GET /partner/v1/assets/{asset_id}/usage-summary`** — the documented endpoint now exists. It returns requests, tokens in and out, cost, unique sessions and average latency for the last `7d`, `30d` or `90d` from `ai_usage_events`. Assets in another tenant return 404 (#99).
- **Collector: per-tenant ingest rate limit** — `POST /ingest/events` now enforces `PS_RATE_LIMIT_PER_MINUTE` (default 100 requests/minute, `0` disables) per tenant, reusing the Partner API's fixed-window limiter. Exceeding it returns `429` with `Retry-After` and `X-RateLimit-*` headers. In-process, so the count is per worker (#82).
- **Gateway: unified, provider-backed `GET /v1/models`** — goes through the same validation as other `/v1` routes, proxies to the configured provider, and returns Anthropic's list shape (with `limit` / `after_id` / `before_id`) when the caller sends `anthropic-version`, so Claude Code can discover models through the gateway; other callers get OpenAI's shape (#79).
- **`route-policy.v1` JSON Schema and golden decision vectors** — `schemas/route-policy/` holds the shared routing contract (JSON Schema 2020-12): groups, quality mapping, sensitivity levels, PII escalation, data policy, per-use-case quality bar and fallback. It also has three example policies and decision vectors in `vectors/*.json`. The gateway router runs every active vector through `resolveRoute`. The SDK checks the schema, the examples and `RouteHint` encoding. Sensitivity, data-policy and quality-bar vectors are marked `pending` and skipped with their reason until those P1 features land (#11).

- **Gateway: token usage and truncation for streamed responses** — gateway telemetry now reads usage from SSE streams as they pass to the client (OpenAI chat `usage` chunks, Anthropic `message_start`/`message_delta`, Responses `response.completed`) and sends the event when the stream ends, so streamed calls are no longer costed at zero. A stream that ends without its terminal event is marked `stream_truncated`, a client disconnect `stream_cancelled`; `/metrics` gains `ps_gateway_streams_total{outcome}` and counts streamed tokens (#72).

- **TypeScript Partner SDK (`@prompt-shields/partner`)** in `packages/partner-ts/`: a typed, dependency-free client for every `/partner/v1` endpoint. It supports OAuth client credentials with token caching or API-key auth, cursor pagination (async iterator, `toArray()`, `listPage()`), retries on 429 that honour `Retry-After`, and typed errors (`APIError`, `RateLimitError`, and others). `assets.usageSummary()` needs the collector endpoint from #99. The package is not yet published to npm (#105).
- **SDK: telemetry for streamed calls** — `stream=True` on the sync and async clients now emits one event when the stream ends, with usage from OpenAI's final usage chunk (when the client points at api.openai.com the SDK requests `stream_options.include_usage` and hides that chunk unless you asked for it; other OpenAI-compatible hosts are left untouched, since some reject the parameter) or Anthropic's `message_start`/`message_delta`, and a ~4-chars-per-token estimate (`tokens_estimated`) otherwise. Events carry `stream_completed` (false on early close or error) and `stream_error`. Chunks pass through unchanged; telemetry failures never break the stream (#91).
- **`ps-scan` repository scanner (SDK)** — `ps-scan [PATH]` statically finds AI usage: LLM SDK imports and clients (OpenAI, Anthropic, Google GenAI, Bedrock, Mistral, Cohere, LangChain, LlamaIndex, LiteLLM), model names, provider base URLs and API-key env var names (never values) in Python, TypeScript/JavaScript, Java and Go. Prints a summary, a JSON report, collector `/ingest/events` bodies with `source="code_scan"`, or SARIF. Standard library only, no network; skips `.env*`, `.git`, `node_modules`, virtualenvs, binaries and large files (#95).

- **SDK: Nordic national-ID detection** — new `national_id` PII category for Swedish personnummer/samordningsnummer (Luhn), Norwegian fødselsnummer/D-/H-numbers (two mod-11 digits), Danish CPR (date, plus mod-11 when unhyphenated) and Finnish HETU (century marker and check character). Dates and checksums are validated to keep phone numbers, order IDs and dates out (#10).
- **Gateway: Gemini 3 tool calling across turns** — thought signatures are returned on tool calls (`function.thought_signature`, non-strict mode) and sent back to Gemini/Vertex; per-part `media_resolution` for images. Ported from Portkey 2.0.0 (#108).
- **Gateway: Bedrock on Portkey 2.0's provider code** — Converse and Messages for Claude (`anthropic_beta` as header string or body array, cache reads and writes in `prompt_tokens`), inference-profile ARNs, batch, files and fine-tuning; IRSA, pod identity, ECS and IMDS credentials for `serviceRole` behind `AWS_AMBIENT_CREDENTIALS_ENABLED` (#108).
- **Gateway: Anthropic structured outputs and effort** — `response_format` JSON schema and `reasoning_effort` map to Anthropic `output_config` (#108).
- **Gateway: Messages and Responses adapter parity** — adapted responses report cached tokens (`cache_read_input_tokens`/`cache_creation_input_tokens` for Messages, `input_tokens_details.cached_tokens` and reasoning tokens for Responses, JSON and streaming); provider-native stop reasons (e.g. Gemini `STOP`, `MAX_TOKENS`, `SAFETY`) map correctly and tool calls report `tool_use`; Messages streams number blocks in order with one stop each and stream reasoning as `thinking` blocks; Responses streams give each function call its own item and end truncated output with `response.incomplete`; tool results sent with text keep the text; Messages errors use Anthropic's error shape; telemetry and metrics count Anthropic-style cache reads and writes in `tokens_in`, so input matches Chat Completions and Responses (#73).
- **Gateway: Responses and Messages API on any provider** — when a provider lacks native support, `/v1/responses` and `/v1/messages` requests (JSON and streaming) are translated through Chat Completions and back, decided per target. Ported from Portkey 2.0.0 (#59).
- **Gateway `/v1/health` and opt-in Prometheus `/metrics`** — `PS_METRICS_ENABLED=true`, optional `PS_METRICS_TOKEN`. Labels include route, status, provider, model and the X-PS business unit and environment, never prompt content. `deployment.yaml` now has liveness and readiness probes (#61).
- **Gateway provider fixes from Portkey 2.0.0** — `prompt_cache_retention`, OpenAI `service_tier` in responses, gpt-image-1 parameters, Azure image-edit transform, Z.ai image generation (#60).

- **Gateway `/v1/rerank`** — a unified, Cohere-style rerank endpoint for Cohere, Jina, Voyage, Bedrock (Agents runtime) and Pinecone. Ported from Portkey gateway 2.0.0 (#58).
- **Gateway providers: Databricks, Latitude, Pinecone** — Databricks takes its workspace from `x-portkey-databricks-workspace`. Ported from Portkey 2.0.0 (#57).
- **Gateway JSON payload-size limit** — set `MAX_JSON_PAYLOAD_SIZE_IN_MB` to reject oversized JSON bodies with 413. Ported from Portkey 2.0.0 (#62).

- **Cost-aware route hints (SDK)** — `RouteHint(quality=, max_cost=, model_group=, allow_cache=)` on `chat.completions.create(route=...)` for both sync and async clients. The SDK never routes; it emits `X-PS-Quality`, `X-PS-Max-Cost`, `X-PS-Route`, and `X-PS-Cache` headers that the gateway acts on (transparent-by-default, per-route override). An empty hint emits no headers.
- **`requested_model` / `served_model` on every event** — the requested model (possibly `"auto"`) is captured alongside the model that actually ran (from the provider response / gateway `X-PS-Served-Model`), so routing savings are provable in Atlas.
- **Gateway cost-aware router** (`gateway/src/middlewares/router/`) — pluggable `RouterStrategy` behind `resolveRoute` with a `HeuristicStrategy` (input-token/code-fence/JSON-schema difficulty → cheap vs. frontier group, `max_cost` budget-clamp across groups). `psRouterMiddleware` rewrites `model="auto"` (or any hinted request) to a concrete model; a concrete model with no hint is left untouched. Config-driven `RoutePolicy` (groups + pricing mirror the SDK) overridable per virtual-key. Fail-open. Telemetry now emits `requested_model`, `served_model`, `route_group`, `route_reason`, `route_est_cost`.
- **Router wired into the gateway pipeline** — `router/hono.ts` exposes `psRouter()`, mounted in `gateway/src/index.ts` (`app.use('*', psRouter())`) ahead of hooks/cache, gated on `PS_ROUTER_ENABLED=true`. Because Hono 4.x re-parses the body per `c.req.json()`, the adapter overwrites `c.req.bodyCache.json` so the rewritten model reaches the handler, and exposes the decision on `c.get('psRoute')`.
- **Telemetry wired into the gateway pipeline** — `ps-telemetry.ts` exposes `psTelemetry()`, a Hono middleware mounted after `psRouter` (gated on `PS_API_KEY`). It parses token usage + served model from the response, merges `X-PS-*` business headers, and folds in `c.get('psRoute')` so `requested_model`/`served_model`/`route_*` actually emit in production. Fire-and-forget, fail-open, POST-only; streaming responses emit without usage.

### Changed

- **SDK: Anthropic `tokens_in` now counts cached prompt tokens** — it is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`, the total prompt size, matching OpenAI `prompt_tokens`. Before, it was `input_tokens` alone, which leaves cache reads and writes out. For prompt-cached workloads, Anthropic `tokens_in` and `cost` will both rise: cache tokens used to be left out of the cost, and are now billed at the cache read and write rates. Use `tokens_cached` and `tokens_cache_write` for the split (#9).

### Fixed

- **Gateway: client disconnects now cancel the upstream stream** — when a client drops a streamed response, the gateway cancels the provider response body, which closes the upstream connection (Node and Workers), so the provider stops generating and billing tokens nobody reads. The log copy of a streamed response no longer tees the body, which also pinned the upstream and buffered the whole stream in memory. Client bytes and `stream_cancelled` telemetry are unchanged. The `/v1/messages` and `/v1/responses` adapter paths do the same, and no longer leave an unhandled writer rejection when the client disconnects.
- **Gateway: batch output streams instead of buffering** — OpenAI, Azure OpenAI and Vertex batch output files are passed through as `application/octet-stream`. Vertex embedding batches read `000000000000.jsonl`, row ids lose a stray `-`, provider errors return error responses, and batch uploads keep multi-byte characters split across chunks. The shared line splitter now emits bytes, which also stops Fireworks dataset uploads from dropping every line. Batch output follows provider-returned locations only to GCS and Azure Blob Storage, and Vertex output resolves `publishers/<provider>/models/...` names to that provider's transform. Ported from Portkey 2.0.0 (#108).
- **Anthropic `prompt_tokens` excluded cached tokens** — they are now included, matching OpenAI's usage convention, so cost and usage reports count cached input (#108).
- **OpenAI batch output fetched `/files/undefined/content`** when a batch had neither an output nor an error file; it now uses the error file, or returns 400 (#108).
- **Bedrock** no longer crashes on a tool call with empty arguments, and adds the text block Converse requires next to a document (#108).

- **Gateway telemetry dropped Messages/Responses token counts** — `input_tokens`/`output_tokens` usage is now counted, which also fixes native Anthropic `/v1/messages` events. Events now carry `api_surface`.

- **Gateway proxy returned 500 for GET/DELETE without a `content-type`** — the catch-all `/v1/*` proxy left the request params undefined, so `tryPost` crashed reading `stream`. Most SDKs send GETs (e.g. `/v1/files`) this way. Body-less requests now proxy with no body, the same method and the upstream response.

- **Gateway telemetry reported vendor `unknown`** — the gateway's telemetry middleware looked for the vendor in the gateway's own URL. It now uses `x-portkey-provider`, or the provider in `x-portkey-config`.

- **Gateway legacy test suites didn't compile** — jest now compiles `src/utils/env.ts` (top-level await) through a test-only transformer, and the legacy handler-service suites run again with mock paths and assertions updated to the current service APIs (#69).

### Security

- **Gateway response cache is scoped to the caller** — the cache key was a hash of the request body and endpoint only, so with caching on, caller B could be served caller A's cached response for an identical body, and identical bodies sent to different `/v1/proxy` paths shared one entry. The key now also covers a SHA-256 digest of the provider, the caller's credential and identity fields (API key, `Authorization` and other credential headers, virtual key, Vertex service account, AWS role, Azure/OAuth client, org/project), any header the gateway forwards upstream (all non-`x-portkey-` headers on `/v1/proxy`, plus `forward_headers`; tracing headers excluded) and the full upstream URL (custom host, path and query). Raw credentials never appear in the key. Keys stay stable for the same caller, including Bedrock `assumedRole`/`serviceRole` while STS credentials rotate. Existing cache entries are unreachable after upgrade (a one-time miss).
- **Gateway: Azure host identity only goes to Azure** — with `AZURE_AMBIENT_CREDENTIALS_ENABLED=true`, `azureAuthMode` `managed` and `workload` (`azure-openai`, `azure-ai-inference`) mint a token for the gateway host's own Azure identity, and a caller could send it anywhere: a `custom_host` or `x-portkey-custom-host`, a resource name such as `evil.example#`, a non-Azure `azureFoundryUrl`, or the Azure proxy path `/v1/proxy/evil.example/x.openai.azure.com/...`. These modes now return 400 before any token request unless there is no custom host, the resource name matches `^[a-z0-9][a-z0-9-]{0,62}$`, and the Foundry URL and final upstream URL are `https`/`wss` on a Microsoft Azure AI host (`*.openai.azure.com`, `*.cognitiveservices.azure.com`, `*.services.ai.azure.com`, `*.models.ai.azure.com`, `*.inference.ai.azure.com`, their `.azure.us`/`.azure.cn` equivalents) with no port or user info. `azureEntraScope` must be the Cognitive Services audience (`https://cognitiveservices.azure.com|us|cn`, optionally `/` or `/.default`), so a caller cannot ask for, say, a `management.azure.com` or `storage.azure.com` token; the only storage token is the one the gateway itself requests to download Azure OpenAI batch output, and only that download may go to Azure Blob Storage (a proxy path such as `/v1/<account>.blob.core.windows.net/...openai.azure.com` is refused). Caller credentials (API key, `azureAdToken`, `entra` with a client secret) still work with custom hosts. Azure ML online endpoints (`*.inference.ml.azure.com`) can no longer use host identity. The Azure guardrails (`contentSafety`, `shieldPrompt`, `protectedMaterial`, `pii`) with `managed` likewise refuse a custom host or a resource name outside that pattern and fail closed; they now ask IMDS for a `https://cognitiveservices.azure.com/` token instead of passing `resourceName` as the IMDS resource.
- **Gateway cache skips multipart and binary requests** — with simple caching on, every multipart (`/v1/audio/transcriptions`, file uploads) or binary body serialised to `{}` and got the same cache key, so one audio file could get another's cached transcript. The cache now only reads and writes JSON request bodies; FormData, Blob, ArrayBuffer, typed-array and stream bodies always go to the provider (cache status `DISABLED`).
- **Collector tenant ingest keys are hashed** — tenants now store a SHA-256 lookup prefix and a bcrypt hash instead of the plaintext key in `settings`. Migration `004` hashes existing keys and removes the plaintext; downgrading cannot restore them. An unknown key and a wrong key get the same 401 after the same bcrypt work (#81).
- **Gateway admin console and log stream require auth** — `/public` and `/log/stream` now need `PS_GATEWAY_ADMIN_TOKEN` (at least 16 characters) as a bearer token or session cookie, and the log stream is disabled when it is unset. Previously anyone who could reach the gateway port could watch live request logs. Provider options and headers are redacted in the stream. Ported from upstream Portkey `main` (#54).
- **`x-portkey-forward-headers` loop guard** — requests or configs that try to forward the forward-headers header itself are rejected with 400 (upstream `de0e6c5`, #55).
- **Upstream URL SSRF check** — provider URLs built from request fields (Azure resource name, Vertex region, AWS region, account ids) may no longer point at metadata, private, link-local or alternatively encoded IPs (#65).
- **Credential masking in gateway logs** — bearer tokens, API keys, AWS and Google keys, and passwords in URLs are masked in the shared logger, the Redis connection log and error logs (#65).
- **Config fan-out cap** — at most 100 root targets (1000 for conditional routing) and 50 nested targets per root target; override with `MAX_ROOT_CONFIG_TARGETS`, `MAX_CONDITIONAL_ROOT_CONFIG_TARGETS` and `MAX_NESTED_CONFIG_TARGETS` (#65).
- **Custom-host response size cap** — responses from custom hosts are limited to 50 MiB (`PS_MAX_CUSTOM_HOST_RESPONSE_BYTES`) (#65).
- **Provider credentials win on proxy routes** — forwarded or proxied client headers no longer overwrite the credential headers a provider config sets (#65).
- **Bedrock/SageMaker cannot borrow the gateway's AWS identity** — `awsAuthType=serviceRole`, and `assumedRole` without operator-configured keys, sign with the host's credentials only when `AWS_AMBIENT_CREDENTIALS_ENABLED=true`; otherwise `serviceRole` returns 403. `assumedRole` without a role ARN returns 400 instead of signing with the operator's assume-role keys. Upstream 2.0 allows all of these for any caller (#108).
- **Azure callers cannot borrow the gateway's Azure identity** — `x-portkey-azure-auth-mode: managed` (host managed identity via IMDS) and `workload` (host federated token) on Azure OpenAI and Azure AI Inference, and `managed` credentials on the Azure guardrails, work only when `AZURE_AMBIENT_CREDENTIALS_ENABLED=true`; otherwise the request returns 403 and the guardrail fails closed (verdict `false`). Upstream allows them for any caller.
- **AWS signed requests stay on AWS** — a crafted `x-portkey-aws-region` (`x@evil.example/`) or S3 bucket name could point Bedrock, SageMaker or STS calls, and their signed headers (access key id, session token), at another host. Regions are now format-checked, signing is refused for hosts outside `AWS_ENDPOINT_DOMAIN`, and STS `RoleArn`/`ExternalId` are URL-encoded (#108).
