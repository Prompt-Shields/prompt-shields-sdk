# LeanIX Integration

Connect Prompt Shields to LeanIX to enrich your IT landscape with discovered AI assets.

<Info>
  The built-in LeanIX connector is a first slice: it pushes AI assets,
  vendors, business units and data flows. It has not yet been verified
  against a live LeanIX sandbox; check the processor configuration in a
  sandbox workspace before using it in production.
</Info>

## How it works

The connector runs in the collector deployment. It reads the tenant's
registry through the **Partner API**, with a partner API key, and writes it to
LeanIX through the **Integration API** as LDIF synchronisation runs:

1. First run: `GET /partner/v1/export`, then `GET /partner/v1/assets/{id}/data-flows` per asset.
2. Later runs: `GET /partner/v1/changes?since=<cursor>` and the flows of the changed assets.
3. Upsert the inbound processor configuration (`PUT /services/integration-api/v1/configurations/`).
4. Start one synchronisation run per batch of assets and wait for it to finish.
5. Store the new cursor in the tenant settings. A failed run leaves the cursor where it was, so the next run retries the same changes.

### Mapping

| PS Data | LeanIX Fact Sheet | External id |
|---------|-------------------|-------------|
| AI Asset | IT Component | `promptshields:asset:<asset id>` |
| AI Vendor | Provider | `promptshields:provider:<vendor>` |
| Business Unit | Organization | `promptshields:business-unit:<name>` |
| Data Flow | Interface | `promptshields:flow:<flow id>` |

Relations: IT Component → Provider (`relITComponentToProvider`) and
Interface → IT Component (`relInterfaceToITComponent`). Retired assets get the
`endOfLife` lifecycle phase; active ones `active` from their first-seen date.
The external ids are the same as the AI-BOM (CycloneDX) `bom-ref` values.

Fact sheets are matched on their `externalId`, so re-running a sync updates the
same fact sheets. Runs use `processingMode: partial` and never delete or
archive fact sheets. IT Component and Interface names carry the first eight
characters of the Prompt Shields id (`Support bot [0190a000]`) because LeanIX
names are unique per fact sheet type.

## Setup

1. In LeanIX, create a technical user with permission to run Integration API
   synchronisations and copy its API token.
2. In Prompt Shields, issue a partner credential for the connector with the
   scopes `export:read`, `changes:read` and `data-flows:read`
   (`POST /api/v1/admin/partner-credentials`).
3. Configure the connector in the collector's environment, per tenant:

```bash
PS_LEANIX='{
  "<tenant uuid>": {
    "workspace_host": "acme.leanix.net",
    "api_token": "<LeanIX API token>",
    "partner_api": {
      "base_url": "https://collector.example.com",
      "api_key": "<partner API key>"
    }
  }
}'
```

Optional per-tenant fields: `connector_id` (default `prompt-shields`; set it
when several Prompt Shields instances feed one workspace),
`include_data_flows` (default `true`) and `batch_size` (assets per run,
default 500). For a collector reached over an internal network, set
`"allow_private_network": true` under `partner_api`; it must still be https.

### Security

- The LeanIX API token and the partner API key live only in the operator
  environment. They are never stored in the database, logged or returned by
  any endpoint; error messages carry status codes, never response bodies.
- `workspace_host` must be a DNS name ending in one of
  `PS_LEANIX_ALLOWED_HOST_SUFFIXES` (JSON list, default `[".leanix.net"]`).
  Calls go only to `https://<workspace_host>`, the host must resolve to public
  addresses, and redirects are never followed.
- Every Partner API read made by the connector is checked against the
  credential's scopes and recorded in the partner audit log.
- Requests time out after 30 seconds; `429`, `5xx` and network errors are
  retried up to four times, honouring `Retry-After`. A run that does not
  finish within 15 minutes fails the sync.

## Running a sync

```bash
# Operator API (Authorization: Bearer $PS_ADMIN_TOKEN)
curl -X POST https://collector.example.com/api/v1/admin/connectors/leanix/sync \
  -H "Authorization: Bearer $PS_ADMIN_TOKEN" \
  -d '{"tenant_id": "<tenant uuid>"}'          # add "full": true to ignore the cursor

curl "https://collector.example.com/api/v1/admin/connectors/leanix/status?tenant_id=<tenant uuid>" \
  -H "Authorization: Bearer $PS_ADMIN_TOKEN"

# CLI
python -m collector.leanix --tenant <tenant uuid> [--full]
```

Schedule the CLI (for example every 4 hours) with your job runner; the
collector has no built-in scheduler yet.

## Do it yourself

You can also pull from the Partner API with LeanIX Integration Hub or your
own job and map the data yourself. Use `GET /partner/v1/export` for the
initial load and `GET /partner/v1/changes?since={last_sync}` afterwards, and
authenticate with OAuth 2.0 client credentials (`POST /oauth/token`) or a
partner API key.
