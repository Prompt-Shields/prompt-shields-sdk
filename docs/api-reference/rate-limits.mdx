# Rate Limits

All Partner API endpoints are rate-limited to protect service stability.

## Tiers

Each partner credential has a rate-limit tier, set by the tenant admin
(see [Authentication](/authentication#managing-scopes-and-tiers-tenant-admins)).
Limits are per credential.

| Tier | Limit |
|------|-------|
| `basic` | 120 requests/minute |
| `standard` (default) | 1,000 requests/minute |
| `premium` | 5,000 requests/minute |
| `enterprise` | 20,000 requests/minute |

An admin can set a custom per-minute limit instead of a tier. Credentials
issued before tiers existed keep their own limit (1,000 unless changed).
`X-RateLimit-Limit` always shows the limit in effect.

## Ingest Limits

`POST /ingest/events` and `POST /ingest/mcp` are limited per tenant API key,
counted together in requests per minute (a batch of events is one request). The default is 100 requests/minute,
set with `PS_RATE_LIMIT_PER_MINUTE` on the collector; `0` turns it off. It
uses the same headers and `429` response as the Partner API. The SDK is
fail-open: a `429` keeps the batch buffered for the next flush and never blocks
the model call.

<Info>
  The limiter is in-process, so each collector worker counts separately.
  Running N workers allows up to N times the configured limit.
</Info>

## Rate Limit Headers

Every response includes rate limit headers:

```
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 847
X-RateLimit-Reset: 1711382460
```

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Maximum requests per minute |
| `X-RateLimit-Remaining` | Requests remaining in current window |
| `X-RateLimit-Reset` | Unix timestamp when the window resets |

## Exceeding the Limit

When you exceed the rate limit, the API returns:

```
HTTP/1.1 429 Too Many Requests
Retry-After: 23
Content-Type: application/json

{
  "type": "about:blank",
  "title": "Too Many Requests",
  "status": 429,
  "detail": "Rate limit exceeded. Retry after 23 seconds."
}
```

**Best practice:** Implement exponential backoff. Respect the `Retry-After` header value.

## Tips for Staying Within Limits

<CardGroup cols={2}>
  <Card title="Use delta sync" icon="arrows-rotate">
    Use `/partner/v1/changes` instead of re-fetching all assets. Fewer requests, same data.
  </Card>
  <Card title="Cache tokens" icon="database">
    OAuth tokens last 1 hour. Don't request a new token per API call.
  </Card>
  <Card title="Use pagination wisely" icon="list">
    Set `limit=200` (maximum) to reduce page count. Default is 50.
  </Card>
  <Card title="Poll sensibly" icon="clock">
    Sync every 4 hours, not every minute. AI asset registries don't change that fast.
  </Card>
</CardGroup>
